四给老师演示：照着点就行

  1. 1企业端登记一物一码 ⭐
    用 ent/123456 登录 → 「商品登记」→ 填名称、上传一张实物图 → 提交 → 页面显示二维码 + 商品编码。这一步会同时写商品表、生成二维码、哈希上链。
  2. 2扫码验真 ⭐⭐
    手机直接扫刚生成的二维码 → 打开手机 HTML 验真页，显示「验真通过 + 商品实物图 + 履历」。
    电脑上也可切到 user/123456 → 扫码验真页 → 手输编码或上传二维码图片 → 点「验真」。
  3. 3质检 / 维修 / 权属转移 ⭐
    回到企业端依次登记「质检」「维修」「权属转移」，每一步都会产生一条新的链上存证。
  4. 4再验真一次，看履历变化 ⭐⭐
    用户端重新验真，履历事件从 1 条变成 4 条 —— 这就是「写操作后缓存立即失效」的实证，也是最能讲清楚的亮点。
  5. 5监管看板收尾 ⭐
    换 admin/123456 → 看权属转移趋势图（7/14/30 天切换）、数据完整性巡检、审计日志。可以现场改一条库里的买家字段再点巡检，mismatch 会点名到被改的商品，演示「链下篡改能查出来」。

五老师用自己的手机 / 别的电脑看

前提：连同一个 WiFi
手机或老师的电脑浏览器打开：
http://192.168.106.221:5173
二维码扫出来是什么
内容是 http://192.168.106.221:8080/api/verify/view?code=...，手机直接打开 HTML 验真页，不是一堆 JSON。
换 WiFi / 换网段后必做：局域网 IP 会变（上面这个 192.168.106.221 是当前的）。IP 一变，二维码里写死的旧地址就失效，需要：① 用新 IP 重启后端 --app.public-base-url=http://新IP:8080；② 登录后调 POST /api/product/refresh-qr 批量重刷历史二维码；③ 真链还要把 backend\fisco\config.toml 的 peers 改成虚机新 IP。详细命令见 局域网演示操作卡.html。
手机摄像头扫不了：内置预览窗口 / WebView 拿不到摄像头授权，不是代码 bug。用系统自带 Edge / Chrome 打开，或在验真页用「上传二维码图片」，或允许地址栏摄像头权限。
